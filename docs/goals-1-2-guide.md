# 目标 1 / 目标 2：CAD 核对与规范规则

实施日期：2026-09-30。继续沿用外部 OCR；未引入新的依赖或改变项目文件夹隔离方式。

## 操作流程

### 1. CAD 与空间模型

1. 在项目对话上传 DXF/DWG。原文件归档到项目的 `.plans` 目录，记录 SHA-256、源格式、单位、转换记录、外部参照和异常。
2. 智能体调用配置的视觉模型读取本机生成的 CAD PNG 预览，并结合 OCR/尺寸实体、真实房间闭合轮廓及图中文字说明空间内容；分析结果逐步出现在聊天中。图纸预览发给已配置的视觉模型服务，原始 DXF 不发送给该模型。
3. 在项目工作区打开“图纸”页，原图在底、识别的房间范围在上。对本次不涉及的空间取消勾选；拖动选中边界上的控制点可做明显修正。读取失败和不能识别的区域会单独提示，不展示内部图层编码让用户处理。
4. 点击“确认空间范围”后保存项目模型版本。系统从图面尺寸标注和单位信息确定比例尺；如果仍缺少可靠尺度或关键设计决定，智能体在聊天中解释缺口，并提供预填分析/推荐项的表格，用户选完后继续。业主不需要填写 CAD 坐标、反射率、网格、构件高度等软件字段。
5. 楼层高度、用途、表面材料等图纸事实缺失时，智能体需区分识别事实与建议假设；不得默认为图纸已标注，也不得要求业主填写无法判断的专业细节。
6. 可在图纸页打开归档原始 CAD，或导出供后续 IFC 转换使用的精确空间模型 JSON。原图曲线源参数与建模边界和预览轮廓抽稀分离。

“边界已确认”不代表所有设计参数已齐备。“设计信息齐备”要求所有有效房间、构件、尺度和完整性检查通过。每次保存产生新模型版本；数据库项目修订历史保留旧模型。

### 2. 逐页证据与标准登记

1. 正式标准可上传到全局资料；企业标准/业主要求也可只作为项目附件，保持项目隔离。材料通过右侧项目工作区管理，不作为顶部固定的聊天卡片。
2. 在项目工作区“规范资料”页逐页核对。PDF 页码是原始文件物理页码，不因空页、扫描页或 OCR 失败而重排。MD/TXT 使用行号，DOCX 使用段落/表格位置，不伪造排版页码。
3. 文本页保留原生块位置、原文表格和单元格位置。含图像/扫描内容的页按需单独送外部 OCR，即使同页已有原生文字也不会直接跳过扫描内容。
4. OCR 表格兼容 Markdown/HTML；原文、脚注和返回的布局坐标保留。服务仅返回纯文本或坐标系不明时，明确标注无可靠 PDF 坐标，不伪造精确定位。OCR 错误或空白页保持可见、待核实；重传可重新识别。
5. 登记编号、版本、标题、实施日期、适用范围、要求类型、发布/授权/业主来源，并人工核实来源。每次登记创建独立版本并固定原文件哈希，不覆盖已有版本。不能用搜索摘要代替全文登记。

### 3. 候选规则与版本绑定

1. 从已登记标准抽取候选。当前支持维持平均照度、均匀度、UGR、Ra/CRI、CCT、LPD。复杂条款或未识别内容可以选择原文块/表格行手动补充。
2. 对照原文填写适用空间用途、评价场景/口径、比较方式、阈值、单位及计算条件。空间用途必须与房间用途一致。一般照明、应急照明等场景应分开，不应通过换名称绕过真实冲突。
3. 工作面规则需确认计算面、相对地坪高度、网格和维护系数；UGR 单独确认评价方法及观察位置/方向。人工输入的计算条件记录为设计假设与复核记录，不能冒充原文规定。
4. 原文身份、引文和位置不可在规则编辑中改写。没有原文数值依据、单位错误、缺失条件、来源未核实、文件哈希改变或同口径冲突时不能确认。表中单独的数字不会自动推断比较方向。
5. 设计人员填写姓名和原文/脚注/适用性复核说明后确认规则；不适用规则需显式记录原因。修改已确认规则会重置为候选。
6. 所有候选已处理、空间信息齐备，并显式确认适用条款无遗漏后，才能绑定当前规则版本与模型版本。按房间、评价场景和评价对象输出 DIALux 设置映射，不机械取最严格阈值，也不把 UGR 观察面当作照度工作面。

## 版本与兼容性

- 原有 SQLite 项目与检索数据继续可读；新表保存逐页原始证据和不可变标准登记，不删除历史项目修订。
- 旧资料没有逐页证据/原文件哈希关联时，需重新上传后才能登记规则来源。旧 CAD 只有摘要时也需重新上传以启用空间模型。
- 重新导入 CAD、校准尺度、编辑房间或构件后，旧规则绑定标记失效；历史结果仅保留用于追溯。新 CAD 不继承旧房间确认状态。
- 修改规则后重新确认、绑定；项目快照固定标准记录和规则集合，不会自动追随后来登记的标准版本。
- 并发编辑使用项目修订号，过期保存返回 409，不覆盖其他已保存修改。

## 主要接口

| 接口 | 用途 |
|---|---|
| `PUT /api/projects/{id}/spatial-model` | 保存逐房间/构件核对及尺度 |
| `GET /api/projects/{id}/spatial-model/export` | 导出完整空间模型与源几何 |
| `GET /api/projects/{id}/floor-plan/source` | 获取归档原 CAD |
| `POST /api/standards`、`GET /api/standards` | 登记/查询明确标准版本 |
| `GET /api/standards/{id}/evidence`、`/source` | 原文位置/归档文件核验 |
| `POST /api/projects/{id}/rules/candidates`、`/manual` | 自动或人工生成有源候选 |
| `PUT /api/projects/{id}/rules/{rule}` | 保存候选修改或不适用原因 |
| `POST /api/projects/{id}/rules/{rule}/confirm` | 设计人员确认规则 |
| `POST /api/projects/{id}/rules/bind` | 固定项目规则与模型版本 |
| `GET /api/projects/{id}/design-settings` | 按房间/场景/对象的准备设置 |

新增回归覆盖等面积异位房间、超过 50 个房间、块变换、不同标高、曲线、完整边界与预览分离、断口、外部参照、混合 PDF、OCR 失败、长表格、资料隔离、篡改证据、冲突、规则绑定与 CAD 更换失效。测试中的阈值均为合成数据，不表示真实标准要求。

注意：

- 任意 CAD 的语义并非百分之百自动识别。无法可靠解析的实体、悬空线段、房间/家具推断均显式列出，需人工补齐或重新整理 CAD。非水平三维几何不冒充可直接使用的水平房间。
- 外部 OCR 的真实接口、授权和实际规范识别质量需要部署环境与真实样本联调；离线测试使用模拟服务。PDF 坐标无法从纯文本响应恢复。
- CAD 图面视觉分析将本机生成的 PNG 预览和图面摘要发送至 `LIGHTING_VISION_MODEL`，或复用支持图像输入的 `LIGHTING_LLM_MODEL`。不上传原始 DXF 给视觉模型；若模型不支持图片，界面/助手必须报告识别失败，不可将几何候选冒充语义理解。
- 大型扫描文档处理较慢。Next 上传代理默认等待 15 分钟，可在前端进程环境或 `web/.env.local` 通过 `LIGHTING_UPLOAD_PROXY_TIMEOUT_MS` 调整；超过部署请求时限的文档建议分卷上传，分别保留原文件与定位。
- 此次不实现自动下载收费/授权标准，也不判断某标准是否为法定最新适用版本；登记来源、版本和适用性由设计人员核实。
- 此次不包含 IFC 文件生成、DIALux 桌面执行、真实照明计算或合规报告。`ready_for_dialux_setup` 仅表示选定模型/规则的准备条件齐备；`simulation_performed` 始终为 `false`，`compliance_status` 为 `not_evaluated`。
