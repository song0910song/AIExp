# 照明智能体实施方案

日期：2026-09-30

## 1. 目标与技术路线

智能体负责资料理解、模型准备、DIALux 操作、方案优化和报告整合；**照明计算与效果渲染必须由 DIALux 完成**。

确定采用 IFC 建模路线：

```text
CAD 导入与检查 → 用户确认空间模型 → 生成 IFC
→ DIALux 导入 → 家具核对与灯具布置 → 计算与导出
→ 规范对照 → 综合报告
```

规范资料为建模、计算设置和结果评估提供约束。灯具资料为选型和光度数据导入提供依据。

实施前提：

- 使用支持所需 IFC 与结果导出功能的 DIALux Pro，并固定经过验证的软件版本。
- 本机 Windows 执行器在可用的交互桌面中操作 DIALux。
- IFC 承载建筑与家具模型；灯具光度数据单独导入、校验和关联。
- 不假设存在覆盖全部操作的公开 API；通过接口验证确定桌面自动化范围。

## 2. 当前状态

| 目标 | 已有能力 | 需要补齐 |
|---|---|---|
| CAD 导入 | DXF/DWG 解析、轮廓和面积候选、用户确认 | 多房间模型、完整性检查、原图叠加核对、门窗家具与标高 |
| 规范引入 | 文档入库、OCR 接口、资料检索 | 逐页证据、表格结构、版本管理、适用性判断和结构化规则 |
| DIALux 设计 | 灯具检索、筛选、通过协议唤起导入 | IFC 建模、布灯、计算设置、真实运行、结果回收与优化 |
| 报告 | 尚无完整链路 | 结果溯源、规范对照、经济性分析和文档输出 |

优先修正两项基础问题：

- CAD 候选按面积和长度去重，可能合并位置不同的同尺寸房间。
- PDF 抽取未保留可靠的逐页定位；混合文本与扫描内容的 PDF 可能漏掉扫描页。

当前的灯具发送不等于导入成功，更不等于完成仿真。现有离线测试及结果快照不能替代真实 DIALux 联调。

## 3. 目标 1：CAD 导入与确认

### 实现流程

1. **文件检查**：保存原文件、哈希和转换日志；检查单位、外部参照、图层、范围及不支持的实体。
2. **几何处理**：展开块引用与变换，处理重复线、断口、弧线和闭合边界；保留修复记录。
3. **语义识别**：按图层、块名、文字位置和几何关系识别房间、门窗、柱及家具。
4. **用户确认**：叠加显示原图与识别结果，支持逐房间核对、尺度校准、边界修正和异常定位。
5. **生成空间模型**：输出供 IFC 转换使用的精确几何及属性，不使用抽稀后的预览轮廓代替建模数据。

### 空间模型字段

- 楼层、房间编号、名称、用途、边界、面积和坐标关系。
- 层高、吊顶、门窗洞口、柱及主要遮挡物。
- 家具类型、位置、尺寸、朝向及材料/反射率。
- 字段来源、置信度、确认状态和模型版本。

原图缺少的高度、材质等列为待确认参数；用户确认的设计假设与原图事实分开记录。

### 验收条件

所有待设计房间均可核对，遗漏与不确定项可见；区分“文件读取完整”与“信息足够用于照明设计”。更换 CAD 后，重新评估旧确认状态和关联结果。

## 4. 目标 2：规范引入与规则管理

### 实现流程

1. **登记标准**：记录编号、版本、实施时间、适用范围、来源和文件哈希，区分正式标准、企业标准与业主要求。
2. **抽取证据**：逐页识别文本和扫描内容，按需 OCR，保留页码、条款、表格、单位、脚注及页面位置。
3. **生成候选规则**：提取适用空间、指标、比较方式、阈值、单位、计算面及附加条件。
4. **确认适用性**：程序校验字段和冲突，设计人员确认关键规则；项目绑定明确的规则版本。
5. **映射计算条件**：将规则要求转为 DIALux 的工作面、网格、维护系数和眩光评价对象等设置。

自动检索优先使用发布机构或授权来源；无法取得正文时提示用户提供，不用搜索摘要代替条文。不同标准需先核对适用条件和评价口径，不能机械地取最严格数值。

### 验收条件

每项设计要求都能追溯至具体标准版本和原文位置。依据不足时标记“待核实”，不得自动判定通过。

## 5. 目标 3：IFC 建模与 DIALux 执行

### 5.1 IFC 模型生成

- 将已确认空间模型转换为 IFC，保留楼层、房间、墙、楼板、门窗开口、家具及材料关系。
- 固定经目标 DIALux 版本验证的 IFC 版本、实体类型和几何表达方式。
- 导入后检查错误日志，核对房间数量、尺寸、标高、开口、家具、坐标及反射率。
- 灯具几何外形不能替代光度数据；实际可计算灯具需另外校验型号、配光文件与安装参数。

### 5.2 家具与灯具布置

- 原图已有家具：识别位置和尺寸，映射到经过验证的三维资产。
- 原图缺少家具：根据空间用途生成参数化方案，用户确认后进入模型。
- 复杂家具：优先采用保留尺寸、遮挡和反射特性的简化模型。
- 灯具：先筛选型号及授权条件，再生成位置、数量、间距、高度和朝向。

家具布置确认后，再确定工作面及眩光评价位置。

### 5.3 本机执行器

新增独立执行组件，与现有问答和 API 服务分离。执行顺序：

1. 检查软件版本、许可、桌面状态及目标工程。
2. 创建工程、导入 IFC，核对模型。
3. 导入灯具光度数据并完成布灯。
4. 设置材料、维护系数、计算面、网格及眩光评价条件。
5. 触发 DIALux 计算，确认计算结束。
6. 保存原生工程，导出数值、文档和渲染图片。

操作优先使用经过验证的接口和界面控件，键盘输入及图像定位作为补充。每一步具备执行后验证、日志、超时、重试和人工接管；重试不得重复创建对象，同一桌面会话串行执行。

### 5.4 结果驱动优化

```text
候选布置 → DIALux 计算 → 读取结果 → 对照规则
→ 调整型号/数量/间距/高度/方向 → DIALux 再计算
```

先优化少量可解释参数，设置运行次数和时间上限。最终方案必须完成正式计算，不能用估算、旧结果或模型回答补齐缺失数据。

### 5.5 运行记录与验收

每次运行绑定 CAD、空间模型、规则、灯具、布置及计算设置版本，记录 DIALux 版本、运行状态和导出文件哈希。

验收必须同时满足：**真实计算完成、原生工程已保存、结果导出成功、结果与本次房间/计算面/场景匹配**。

## 6. 目标 4：结果报告

报告分为“DIALux 原始成果包”和“智能体综合报告”。数值优先从 XML/CSV 获取，未覆盖内容从固定模板 PDF 提取，OCR 作为兜底；关键字段缺失或低置信度时人工复核。各格式的字段覆盖先通过样例验证。

| 内容 | 数据依据 |
|---|---|
| 维持平均照度、U₀ | 对应计算面和场景的 DIALux 结果，保留维护系数等条件 |
| UGR | 按适用规范确定评价方法，保留观察位置、方向或表格法条件，不用目录值替代 |
| Ra、CCT | 实际灯具型号的厂家/测试资料及导入产品数据，缺失时明确标记 |
| LPD | 同口径 DIALux 输出；若由功率和面积派生，注明公式及范围 |
| 灯具清单、效果图 | 最终工程实际使用清单和本次 DIALux 渲染 |
| 规范对照 | 已确认规则与对应结果，区分符合、不符合、信息不足、不适用 |
| 价格、节能 | 有日期和范围的报价、基准方案、运行时数、控制策略及电价 |

每项关键数字关联运行记录和原始文件位置。成本加总与节能测算单独标注，不冒充照明仿真或实测节能。

## 7. 实施顺序

| 阶段 | 交付物 | 验收重点 |
|---|---|---|
| 0. 桥接验证 | 单房间 IFC、少量家具灯具、真实 DIALux 工程与导出结果 | 验证导入质量、自动化可达性和结果字段；允许人工辅助 |
| 1. CAD 模型 | 多房间空间模型、原图核对界面、完整性清单 | 不漏房间，坐标与尺寸正确，不确定项可见 |
| 2. 规范规则 | 逐页证据、已确认规则集、计算条件映射 | 版本明确、条件一致、可追溯 |
| 3. 自动执行 | IFC 导入、布灯、计算、结果回收和有限迭代 | 可重复运行、可恢复失败、结果与方案严格对应 |
| 4. 综合报告 | 原始成果包、规范对照及经济性分析 | 数据有依据，未确认项明确，结论不越界 |

从阶段 0 开始归档原始成果，避免最后才发现报告缺少关键数据。

**最终验收：真实 CAD → 确认模型与规则 → 可打开的 DIALux 工程 → 真实计算结果 → 可追溯报告。**
