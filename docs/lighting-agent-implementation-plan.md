# 照明智能体实施方案

日期：2026-09-30（重大修订：2026-10-08）

## 1. 目标与技术路线

智能体负责资料理解、模型准备、DIALux 操作、方案优化和报告整合；**照明计算与效果渲染必须由 DIALux 完成**。

确定采用 IFC 建模路线，并改为模型自主判断与自动执行：

```text
CAD 导入与检查 → 多模态模型分析空间范围/语义/假设
→ 确定性几何与规则校验 → 自动生成 IFC
→ DIALux 导入 → 自动布置与计算 → 导出
→ 规范对照 → 综合报告
```

### 重大变更：完全自动判断与启动

本版本采用用户已确认的全自动策略：CAD 转 IFC 过程中不再要求人工选择候选房间、逐项确认空间模型或确认 DIALux 默认假设；模型自动决定纳入本次设计的空间、排除外轮廓/重复候选/注释实体，自动补齐可审计的设计假设，并在判断通过后自动生成 IFC、准备 DIALux 任务并启动真实计算。用户不再是执行前置闸门，人工只作为运行失败、证据冲突或结果复核时的接管角色。

“完全自动”不代表模型可以忽略不确定性。模型必须输出结构化判断、证据定位、置信度、冲突和假设；确定性几何/规则校验是强制门槛。无法证明 IFC 表达安全、模型判断互相矛盾、尺度不可换算、楼层/宿主关系不唯一或 DIALux 控件状态不可验证时，系统自动停止并进入 `needs_attention`，不得静默近似、删除候选或声称已计算。该停止是机器判断结果，不是请求用户提前确认。

自动执行采用幂等状态机：`cad_ingested → model_analyzing → model_validated → ifc_generated → dialux_prepared → dialux_running → completed`；异常进入 `needs_attention`，保留原 CAD、模型判断、规则校验、IFC、UI 证据和失败截图，可从不可变输入恢复。每次执行绑定源 CAD 哈希、模型版本、模型判断哈希、假设哈希、IFC 哈希、光度文件哈希和 DIALux 版本。

规范资料为建模、计算设置和结果评估提供约束。灯具资料为选型和光度数据导入提供依据。

实施前提：

- 使用支持所需 IFC 与结果导出功能的 DIALux Pro，并固定经过验证的软件版本。
- 本机 Windows 执行器在可用的交互桌面中操作 DIALux。
- IFC 承载建筑与家具模型；灯具光度数据单独导入、校验和关联。
- 不假设存在覆盖全部操作的公开 API；通过接口验证确定桌面自动化范围。

## 2. 当前状态

| 目标 | 已有能力 | 需要补齐 |
|---|---|---|
| CAD 导入 | DXF/DWG 解析、轮廓和面积候选、视觉分析辅助 | 模型自动空间选择、语义识别、完整性判断、门窗家具与标高推断、自动 IFC 就绪判定 |
| 规范引入 | 文档入库、OCR 接口、资料检索 | 逐页证据、表格结构、版本管理、适用性判断和结构化规则 |
| DIALux 设计 | 灯具检索、筛选、官方 ULD 缓存、受控桌面执行 | 模型自主选型/布灯、自动 IFC 建模、自动启动真实计算、结果回收与优化 |
| 报告 | 尚无完整链路 | 结果溯源、规范对照、经济性分析和文档输出 |

优先修正两项基础问题：

- CAD 候选按面积和长度去重，可能合并位置不同的同尺寸房间。
- PDF 抽取未保留可靠的逐页定位；混合文本与扫描内容的 PDF 可能漏掉扫描页。

当前的灯具发送不等于导入成功，更不等于完成仿真。现有离线测试及结果快照不能替代真实 DIALux 联调。

## 3. 目标 1：CAD 导入与模型自主判断

### 实现流程

1. **文件检查**：保存原文件、哈希和转换日志；检查单位、外部参照、图层、范围及不支持的实体。
2. **几何处理**：展开块引用与变换，处理重复线、断口、弧线和闭合边界；保留修复记录。
3. **多模态模型分析**：将原始 CAD 几何、渲染预览、文字/尺寸标注、图层语义和确定性解析结果作为证据输入模型；识别房间用途、空间关系、门窗、柱、家具、楼层、标高和照明限制，并为每个判断给出证据定位与置信度。
4. **模型自动决定范围**：模型自动区分设计空间、外轮廓、重复边界、图框、注释和不参与照明的实体；不得按面积单独去重。每个保留/排除决定都写入 `model_decisions`，保留原候选和排除原因。
5. **确定性校验**：程序检查单位、尺度、闭合性、自交、重叠、楼层一致性、门窗宿主、实体支持范围和 IFC 表达能力；模型判断不得覆盖硬校验失败。
6. **自动生成空间模型**：校验通过即自动标记模型状态为 `auto_confirmed`，生成供 IFC 转换使用的精确几何及属性，不使用抽稀后的预览轮廓代替建模数据。

### 空间模型字段

- 楼层、房间编号、名称、用途、边界、面积和坐标关系。
- 层高、吊顶、门窗洞口、柱及主要遮挡物。
- 家具类型、位置、尺寸、朝向及材料/反射率。
- 字段来源、证据定位、模型置信度、冲突、自动判断状态、假设及模型版本。

原图缺少的高度、材质等由模型按项目规则生成明确假设，并与原图事实分开记录；假设必须带影响范围和来源。模型无法形成唯一、可审计且可被 IFC/DIALux 表达的判断时自动阻断。

### 验收条件

所有自动纳入/排除的空间均有证据和原因；区分“文件读取完整”“模型判断完成”“几何校验通过”和“信息足够用于照明设计”。更换 CAD、模型或规则版本后，自动使旧判断、IFC 和 DIALux 任务失效并重新分析。

## 4. 目标 2：规范引入与规则管理

### 实现流程

1. **登记标准**：记录编号、版本、实施时间、适用范围、来源和文件哈希，区分正式标准、企业标准与业主要求。
2. **抽取证据**：逐页识别文本和扫描内容，按需 OCR，保留页码、条款、表格、单位、脚注及页面位置。
3. **生成候选规则**：提取适用空间、指标、比较方式、阈值、单位、计算面及附加条件。
4. **确认适用性**：程序校验字段和冲突，设计人员确认关键规则；项目绑定明确的规则版本。
5. **映射计算条件**：将规则要求转为 DIALux 的工作面、网格、维护系数和眩光评价对象等设置。

自动检索优先使用发布机构或授权来源；无法取得正文时提示用户提供，不用搜索摘要代替条文。不同标准需先核对适用条件和评价口径，不能机械地取最严格数值。

### 验收条件

每项设计要求都能追溯至具体标准版本和原文位置。依据不足时标记“待核实”，不得自动判定通过。

## 5. 目标 3：IFC 建模与 DIALux 执行

2026-10-06 增量：独立执行器完成固定原生工程重算，并完成从 IFC/IES 创建**合成双房间 envelope 工程**的全程实机验收：共墙只生成一次，关闭不透明门通过 `IfcOpeningElement` 宿主关系表达，测试玻璃显式回读透射率/折射率，自动布置两盏灯，关闭自然光，真实计算，分别导出并解析两个房间的 PDF，导出光线追踪图，最后重开工程并复核结果与材质。详见 [独立执行器说明](dialux-standalone-executor.md) 和 [桥接验证记录](dialux-phase0-bridge-validation.md)。

当前已完成固定合成 profile 和一份真实 DXF 单房间 profile 的独立验收。真实 CAD 的确认模型、源文件哈希、IFC 生成、DIALux 实际计算、PDF/光追导出及工程重开均已形成可追溯证据；任意 DWG、任意厂家 IES、多灯布局、复杂墙体和布局优化仍需单独验收。执行器保持独立 CLI，同时由智能体/API 编排准备、确认、启动和结果回收。

### 5.1 IFC 模型生成

范围确认（2026-10-06）：用户明确目标 3 **不包含自然光计算**。只实施人工照明场景、真实计算与结果验收；不生成日光场景或日光指标。当前 profile 默认门为关闭、普通不透明门扇；开放通道必须显式声明为 `open_passage`，不能把缺少门扇默认为开门。玻璃必须显式提供厚度、可见光透射率和折射率。门窗仍属于建筑几何和人工照明遮挡/反射模型。

- 将模型自动确认且通过确定性校验的空间模型转换为 IFC，保留楼层、房间、墙、楼板、门窗开口、家具及材料关系。
- 固定经目标 DIALux 版本验证的 IFC 版本、实体类型和几何表达方式。
- 对合成双房间 profile，共墙只生成一个宿主墙体；门洞通过 `IfcOpeningElement` 表达，关闭门扇通过宿主关系填充，开放通道不创建门扇。
- 对真实 CAD 通用 profile，保留模型自动选定的单房间精确平面轮廓（曲线按建模容差采样，支持孔洞和斜墙）及源句柄；闭合不规则家具/柱体也保留外环与内孔。其他房间候选由模型显式排除并记录证据；多层、复杂多房间共墙拓扑、无效几何和不确定门窗宿主由自动校验阻断。
- 导入后检查错误日志，核对房间数量、尺寸、标高、开口、家具、坐标及反射率。
- 灯具几何外形不能替代光度数据；实际可计算灯具需另外校验型号、配光文件与安装参数。

### 5.2 家具与灯具布置

- 原图已有家具：识别位置和尺寸，映射到经过验证的三维资产。
- 原图缺少家具：根据模型识别的空间用途生成参数化方案，记录为自动假设后直接进入模型；无法确定用途或家具会改变计算结果时自动阻断。
- 复杂家具：优先采用保留尺寸、遮挡和反射特性的简化模型。
- 灯具：先筛选型号及授权条件，再生成位置、数量、间距、高度和朝向。
- 当前双房间验收使用两盏固定合成 IES；每个房间一盏，位置、光通量、功率和调光值均在 DIALux 中回读。

模型自动确定家具、工作面及眩光评价位置，并将用途、规则证据和计算面绑定；无适用规则时不得伪造合规结论。

### 5.3 本机执行器

新增独立执行组件，与现有问答和 API 服务分离。执行顺序：

1. 检查软件版本、许可、桌面状态及目标工程；任务由自动模型判断触发，不等待用户确认。
2. 创建工程、导入 IFC，核对模型。
3. 导入灯具光度数据并完成布灯。
4. 设置材料、维护系数、计算面、网格及眩光评价条件。
5. 触发 DIALux 计算，确认计算结束。
6. 保存原生工程，导出数值、文档和渲染图片。

操作优先使用经过验证的接口和界面控件，键盘输入及图像定位作为补充。每一步具备执行后验证、日志、超时、重试和人工接管；重试不得重复创建对象，同一桌面会话串行执行。模型判断通过后自动调用执行器并启动真实计算；仅在 UI 状态不可验证、未知弹窗、结果错配或输入校验失败时进入 `needs_attention`。当前已验证真实 DXF 派生 IFC 导入、正交阶梯房间工作面、IES 回读、单灯布置、人工照明计算、PDF、光线追踪及工程重开链路；复杂单房间 IFC 已有本地实体几何测试，DIALux 实机导入/计算尚未验收；合成双房间 profile 另已验证门窗材质和双 PDF。

### 5.4 结果驱动优化

```text
候选布置 → DIALux 计算 → 读取结果 → 对照规则
→ 调整型号/数量/间距/高度/方向 → DIALux 再计算
```

先优化少量可解释参数，设置运行次数和时间上限。最终方案必须完成正式计算，不能用估算、旧结果或模型回答补齐缺失数据。

### 5.5 运行记录与验收

每次运行绑定 CAD、空间模型、规则、灯具、布置及计算设置版本，记录 DIALux 版本、运行状态和导出文件哈希。

验收必须同时满足：**真实计算完成、原生工程已保存、结果导出成功、结果与本次房间/计算面/场景匹配**。双房间 profile 还要求两个房间的结果监视器与各自 PDF 数值一致、工作面编号分别绑定、重开后结果与玻璃/门材质仍一致。

2026-10-06/07 接入与验证：已将通用执行任务接入项目智能体和 HTTP API。2026-10-08 重大变更后，智能体不再等待用户确认空间模型或默认假设：`prepare_dialux_run` 由自动 CAD 模型判断结果触发，模型通过确定性校验后立即生成不可变任务包并自动调用 `start_dialux_run`。传入搜索候选的 `luminaire_id` 时，系统从 DIALux 官方 `dial://` 链接自动缓存 ULD，并将缓存文件作为不可变输入绑定哈希；不再要求用户重复上传 IES/LDT/ULD。`send_luminaire_to_dialux` 和工作台按钮仍只负责唤起本机导入对话框，不能把导入唤起本身当作计算完成。`get_dialux_run` 回收任务状态和 DIALux 原始结果。除合成 v7 外，2026-10-07 的真实 `sample-room.dxf` 单房间运行也在 DIALux `5.14.0.3` 完成 IFC 导入、人工照明计算、原生工程重开、PDF 和光线追踪导出；两次失败尝试按执行器策略保留并从不可变输入恢复，最终 attempt-003 完成且 IFC 导入报告为 0 警告/错误。真实 CAD 结果为 `5.09 lx / U₀ 0.13`，未达到报告内置 `500 lx / 0.60` 目标，详见 [独立执行器说明](dialux-standalone-executor.md)。

通用 profile 按自动模型判断策略执行：单房间任意有效平面轮廓（含 1 mm 容差曲线采样、孔洞、斜墙）及闭合不规则构件可保留为 IFC4 挤出轮廓；矩形多房间继续由共享墙 envelope 表达，同层、间距及重叠关系通过校验的非矩形房间可由多边形围护表达。多楼层、重叠/墙厚关系含糊、复杂房间门窗宿主未确认的模型进入 `needs_attention`，不压成外包矩形。复杂 IFC 几何目前已覆盖本地实体/序列化和自动化回归测试，尚未完成 DIALux 实机导入与计算验收。真实 DXF 验收已覆盖阶梯形单房间、其他候选显式排除、ACAD_TABLE 注释实体核对和源哈希绑定。布局候选生成和最多 8 个独立 DIALux 真实重算的编排已经实现，但多候选优化尚未实机验收。平均照度和均匀度为硬约束；只有所有房间指标完整且约束达标才会报告可行候选，否则明确标为无可行候选。当前 profile 不能验证总输入功率，功率上限及减功率/减灯具数目标会被 readiness 阻断；不把 DIALux 的功率密度字段冒充总功率，也不声称优化了能耗或灯具数量。

## 6. 目标 4：结果报告

报告分为“DIALux 原始成果包”和“智能体综合报告”。数值优先从 XML/CSV 获取，未覆盖内容从固定模板 PDF 提取，OCR 作为兜底；关键字段缺失或低置信度时人工复核。各格式的字段覆盖先通过样例验证。

| 内容 | 数据依据 |
|---|---|
| 维持平均照度、U₀ | 对应计算面和场景的 DIALux 结果，保留维护系数等条件 |
| UGR | 按适用规范确定评价方法，保留观察位置、方向或表格法条件，不用目录值替代 |
| Ra、CCT | 实际灯具型号的厂家/测试资料及导入产品数据，缺失时明确标记 |
| LPD | 同口径 DIALux 输出；若由功率和面积派生，注明公式及范围 |
| 灯具清单、效果图 | 最终工程实际使用清单和本次 DIALux 渲染 |
| 规范对照 | 已确认规则与对应结果，区分符合、不符合、信息不足、不适用 |
| 价格、节能 | 有日期和范围的报价、基准方案、运行时数、控制策略及电价 |

每项关键数字关联运行记录和原始文件位置。成本加总与节能测算单独标注，不冒充照明仿真或实测节能。
