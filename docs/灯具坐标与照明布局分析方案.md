# 灯具坐标与照明布局分析方案

## 1. 文档定位

本文档用于定义照明设计智能体的“灯具坐标与照明布局分析”能力。

目标不是让模型直接凭经验画灯，而是让智能体完成以下闭环：

```text
图纸与设计报告
    -> 提取房间、灯具、坐标、安装高度和对象
    -> 统一 DXF/DWG/PDF 坐标与身份
    -> 分析数量、边界、间距、阵列和冲突
    -> 判断通用照明/重点照明候选分组
    -> 生成可解释的候选布灯方案
    -> 交给 DIALux 或等效软件进行最终复核
```

该能力应定位为“可审查的布局分析与方案辅助”，而不是不经过专业仿真的自动合规设计器。

## 2. 需要解决的问题

目前照明项目中的灯具信息通常分散在多个文件中：

- DXF/DWG 保存图形、图层、房间边界、家具和灯具符号；
- DIALux PDF 报告保存灯具清单、型号、坐标、安装高度和计算结果；
- IES/LDT/ULD 文件保存灯具的配光数据；
- 设计师的口头说明或任务书保存照明用途、控制分区和重点照明意图。

如果只读取其中一个文件，智能体最多只能回答“有多少盏灯”。完整的布局分析还需要回答：

1. 每盏灯在哪里？
2. 这盏灯属于哪种型号、哪一类照明和哪一个分区？
3. 图纸上的灯具是否与报告清单一致？
4. 灯具之间、灯具与墙体或家具之间的距离是否存在异常？
5. 当前阵列是规则布置、局部重点布置，还是可能存在漏灯、错位或重复？
6. 如果重新布置，哪些方案更可能改善照度、均匀度、眩光或能耗？

## 4. 能力边界

### 4.1 第一层：还原当前设计

这一层的目标是准确提取已有设计，不改变设计意图。输出每盏灯的位置、型号、安装高度、来源和所属候选分组。

这一层可以较早实现，并可作为后续所有功能的数据基础。

### 4.2 第二层：分析当前布局

这一层对已有位置做确定性几何分析，包括数量一致性、越界、间距、阵列规律、重叠和与障碍物的关系。

这些结果可以直接由几何算法得到，但“是否满足照度标准”仍不能只由几何分析得出。

### 4.3 第三层：生成候选布局

这一层根据房间、目标照度、灯具配光和设计约束生成若干候选位置。候选位置需要经过快速光度预览筛选，再交由 DIALux 或等效软件完成最终验证。

### 4.4 不应直接承诺的内容

- 不能仅凭坐标判断平均照度、均匀度或 UGR 合格；
- 不能在报告没有照明用途说明时，武断地把某类灯具认定为重点照明；
- 不能从普通灯具图形推断灯具的真实配光、朝向或调光状态；
- 不能在没有确认坐标系、单位和房间边界时自动修改原始 CAD；
- 不能把算法生成的候选布灯位置表述为最终施工图；
- 不能用产品目录中的 UGR 字段替代项目空间的 UGR 计算。

## 5. 数据模型

建议在现有 `ProjectState` 基础上增加以下对象。

### 5.1 `LuminairePlacement`

表示一盏灯在某个项目版本中的位置。

```json
{
  "placement_id": "L-021",
  "luminaire_id": "candidate-ceah-m6311",
  "model": "CEAH-M6311",
  "category": "general_candidate",
  "x_m": 6.635,
  "y_m": 14.166,
  "z_m": 4.144,
  "rotation_deg": 0.0,
  "footprint": {
    "length_m": null,
    "width_m": null
  },
  "group_id": "general-01",
  "source_refs": [
    "output.dxf:DLX_LUM:entity-1234",
    "设计案_报告.pdf:page-17"
  ],
  "confidence": "high"
}
```

需要保留原始实体句柄或页码，不能只保存解析后的坐标。这样用户点击问题时，智能体才能回到原始证据。

### 5.2 `LayoutCheck`

表示一次确定性的检查结果。

```json
{
  "metric": "nearest_neighbor_distance",
  "status": "warning",
  "observed": 0.67,
  "threshold": null,
  "unit": "m",
  "placement_ids": ["L-034", "L-035"],
  "explanation": "相邻灯具中心距较小，需结合灯具实际尺寸和旋转方向复核。",
  "source_refs": ["output.dxf:DLX_LUM"]
}
```

### 5.3 `LayoutIssue`

表示需要设计师处理的问题。问题应包含严重程度、位置、证据和建议，而不是只有一段自然语言。

```json
{
  "issue_id": "layout-issue-001",
  "severity": "warning",
  "kind": "possible_overlap",
  "placement_ids": ["L-034", "L-035"],
  "location": {"x_m": 3.45, "y_m": 15.27},
  "message": "两盏灯的中心距小于灯具名义长度，可能存在实体重叠。",
  "required_action": "确认灯具旋转方向、实际外形尺寸和是否为连续排列。",
  "confidence": "medium"
}
```

### 5.4 `LayoutCandidate`

表示待复核的候选方案，而不是已经通过的设计。

应保存：

- 方案所属的项目 revision；
- 所使用的灯具和配光文件哈希；
- 每盏灯的位置和旋转角度；
- 房间、障碍物和工作面约束；
- 目标函数和权重；
- 几何检查结果；
- 快速预览结果；
- DIALux 验证状态；
- 不可行原因或用户接受记录。

## 6. DXF、DWG 和 PDF 的数据关联

### 6.1 DXF 解析

应从 DXF 中提取：

- 文件头单位和实际比例；
- 房间轮廓和闭合区域；
- 墙体、门窗、开口和家具图层；
- 灯具图层、块或重复图形；
- 文本标注和灯具编号；
- 照明计算区域和网格；
- 每个原始实体的句柄、图层和包围盒。

当前文件中已经观察到以下 DIALux 图层：

| 图层 | 可能含义 |
|---|---|
| `DLX_CONT` | 房间轮廓或墙体 |
| `DLX_APERT` | 门窗和开口 |
| `DLX_LUM` | 灯具图形 |
| `DLX_OBJ` | 家具或室内对象 |
| `DLX_CALC` | 照明计算区域 |
| `DLX_GIRD` | 照明计算网格 |
| `DLX_LUMKEY` | 灯具表 |
| `DLX_LUMKEY_IDX` | 灯具索引文字 |

需要特别处理当前 DXF 的特点：灯具可能不是带插入点的标准 CAD 块，而是由多条线段组成的重复符号。此时不能把每条线段当作一盏灯，应通过以下方式提取灯具中心：

1. 优先读取 `INSERT` 块的插入点；
2. 如果只有线段，按图层、拓扑连接、几何距离和重复符号模板聚类；
3. 对每个符号计算实际包围盒中心或设计基准点；
4. 保存组成该符号的实体句柄集合；
5. 通过灯具索引文字、符号数量和 PDF 坐标进行交叉验证。

当前 `DLX_LUM` 约有 2592 条线段，平均每套灯具约 72 条线段，推断为 36 个重复灯具符号。这个比例可以作为当前文件的回归测试依据，但不应写死为所有 DXF 的通用规则。

### 6.2 PDF 报告解析

报告中通常比 CAD 更容易直接读出以下字段：

- 灯具编号；
- 产品编号和产品名称；
- 数量；
- X、Y、Z 坐标；
- 安装高度；
- 单灯功率和光通量；
- 工作面高度；
- 平均照度、最小照度、最大照度；
- 均匀度和眩光评价；
- 墙、顶棚、地面反射率；
- 设计场景和计算区域。

PDF 页面坐标不是图纸空间坐标，不能根据文字在 PDF 页面上的位置推断灯具位置。应读取报告中明确打印出的 X/Y/Z 数值，并保留页码和附近型号信息。

### 6.3 坐标系统一

DXF 与 PDF 可能存在原点、比例、旋转方向或单位差异。统一时应使用二维相似变换：

```text
P_report = s * R * P_dxf + t
```

其中：

- `s` 是比例；
- `R` 是旋转矩阵；
- `t` 是平移向量。

推荐流程：

1. 先检查图纸单位和专属图层约定；
2. 通过房间边界和至少三个匹配灯具寻找锚点；
3. 计算平移、旋转和比例；
4. 用未参与拟合的灯具计算残差；
5. 残差超过可配置阈值时，标记为坐标不一致；
6. 未经用户确认，不把变换后的坐标写回项目事实。

当前 DIALux 图层的坐标应优先按米解释。文件头中的 `$INSUNITS` 不能单独作为可靠依据，因为导出文件可能声明为英制，但实际几何明显按米制使用。

## 7. 灯具匹配与一致性检查

### 7.1 灯具数量检查

需要比较：

- DXF 中识别出的灯具符号数量；
- PDF 灯具位置明细数量；
- PDF 灯具清单数量；
- `DLX_LUMKEY_IDX` 中的型号索引数量。

当前项目的数量关系为：

```text
DXF 灯具符号：36
PDF 灯具清单：16 + 20 = 36
灯具索引文字：36
```

因此当前文件在数量层面是一致的。

### 7.2 型号和参数检查

应检查每个型号的：

- 品牌；
- 产品编号；
- 数量；
- 单灯功率；
- 光通量；
- 色温；
- 显色指数；
- 配光文件名称和哈希。

当前报告中总光通量为 104944 lm，而根据部分 DXF/产品字段按 2958 lm 计算会得到略有差异的数值。这很可能是报告使用 2959 lm、原始产品字段使用 2958 lm 造成的舍入差异。系统应显示“舍入差异”，而不是简单判定为型号错误。

报告中 CDN 产品名称包含 5700K，但产品数据页还出现 6800K 字段；PAK 产品数据为 5000K。色温字段应列为参数冲突，要求确认后再参与选型或合规判断。

### 7.3 坐标匹配

推荐的匹配优先级：

1. 明确的灯具编号或块属性；
2. 型号和索引；
3. 坐标变换后的最近邻；
4. 安装高度和符号尺寸；
5. 人工确认。

匹配结果应分为：

- `matched`：身份和坐标均一致；
- `coordinate_mismatch`：型号可能一致，但坐标残差过大；
- `missing_in_dxf`：报告有，图纸没有；
- `missing_in_report`：图纸有，报告没有；
- `duplicate`：多个图形疑似对应同一盏灯；
- `unresolved`：无法可靠匹配。

## 8. 坐标与间距分析

### 8.1 灯具到边界的距离

对每盏灯计算其中心到房间边界的最短距离：

```text
d_boundary = min(distance(point, every_room_boundary_segment))
```

同时应考虑灯具实际外轮廓，而不是只看中心点。需要标记：

- 灯具中心在房间外；
- 灯具外轮廓跨越墙线；
- 灯具距离墙体过近；
- 灯具处于门扇开启范围；
- 灯具靠近柱、风口或其他不可安装区域。

“离墙多少米合适”不能使用一个对所有项目都相同的固定值。边界距离规则应来自项目约束、灯具安装要求或经确认的设计经验，并注明证据来源。

### 8.2 灯具之间的距离

两盏灯中心距为：

```text
d(i,j) = sqrt((x_i - x_j)^2 + (y_i - y_j)^2)
```

至少应统计：

- 最近邻距离；
- 同一排相邻距离；
- 同一列相邻距离；
- 最大和最小间距；
- 平均间距和标准差；
- 间距变异系数；
- 同型号与异型号之间的距离分布。

对于数量较少的房间，可以计算全部灯具对；对于大楼层图纸，可以用空间索引获取近邻，避免不必要的全量计算。

### 8.3 行列和阵列识别

可使用以下方法识别规则布置：

- 按 X/Y 坐标容差聚类；
- 对灯具点集进行主方向分析；
- 沿主方向投影并排序；
- 用中位数间距推断候选网格；
- 检查网格中的缺失点、重复点和偏移点；
- 对线性排列识别首尾、间距和方向。

对于每个阵列，应输出：

```text
阵列 A
方向：沿 Y 方向
灯具数量：6
平均中心距：2.47 m
最大偏差：0.04 m
状态：基本规则
```

如果某一排出现明显不同的间距，不能立即判定为错误，还需要检查它是否属于重点照明、避让家具或建筑构件。

### 8.4 灯具实体重叠

只有在获取灯具实际尺寸和旋转方向后，才能可靠判断重叠。算法应把每盏灯转换为旋转矩形或产品外轮廓，再检查：

- 外轮廓是否相交；
- 安装维护空间是否相交；
- 连续灯具之间是否符合产品安装要求；
- 灯具是否碰撞墙体、柱、风口或家具。

当前 PAK 灯具相邻中心距约为 0.62～0.80 m，而报告中产品尺寸包含约 1.198 m 的长度。这个结果需要重点复核灯具方向、产品实际外形和是否为连续排列；它是“可能重叠”风险，不应在没有旋转和外轮廓信息时直接判定为错误。

### 8.5 空间覆盖和空洞区域

在房间工作面上建立分析网格，计算每个网格点到最近灯具的距离或灯具影响权重，可用于发现：

- 某个区域没有灯具覆盖；
- 灯具集中在局部，其他区域过空；
- 靠墙区域缺少灯具；
- 重点区域有灯具，但通用工作面没有得到均匀覆盖。

这一步只是几何覆盖分析。要得到照度热力图，必须使用 IES/LDT 配光文件和明确的安装高度、反射率及工作面参数。

## 9. 通用照明与重点照明判定

### 9.1 证据优先级

照明类别的判断应遵循以下证据优先级：

1. 报告中明确的灯光场景、回路、用途或对象名称；
2. CAD 图层、块属性、编号规则或设计说明；
3. 灯具产品类型、配光角、方向和安装方式；
4. 灯具与会议桌、讲台、展示墙等对象的空间关系；
5. 规则模型基于阵列和距离给出的候选判断。

如果只有第五类证据，结果必须标记为“推断”，并要求用户确认。

### 9.2 通用照明的识别特征

通用照明通常：

- 覆盖整个房间或主要工作面；
- 具有规则网格或相对均匀的重复阵列；
- 以水平工作面照度和均匀度为主要目标；
- 灯具间距具有相对稳定的统计分布；
- 与房间功能区域整体对应，而非只指向单一对象。

### 9.3 重点照明的识别特征

重点照明通常：

- 靠近展示墙、讲台、背景墙、艺术品或标识；
- 具有明确朝向或可调角度；
- 与目标对象距离和方向存在稳定关系；
- 使用较窄配光或较高局部照度；
- 可能单独属于一个控制回路或灯光场景；
- 重点考察垂直面照度、亮度或视觉层次。

### 9.4 当前项目的合理判断

当前资料没有明确写出两类灯具分别属于哪个照明回路或功能场景，因此智能体不应直接给出确定结论。

可以输出以下候选判断：

| 灯具 | 几何观察 | 候选判断 | 置信度 |
|---|---|---|---|
| CDN CEAH-M6311 | 主要分布在较规则的 X/Y 阵列中 | 通用照明或通用照明候选 | 中 |
| PAK PAK41101Y | 在房间中部形成密集的线性排列 | 会议区域通用照明候选，也需排查连续排列/局部照明意图 | 中 |

如果报告、CAD 或用户没有提供展示墙、讲台、会议桌方向和回路信息，智能体应把分组状态设为 `needs_confirmation`，而不是自行决定“重点照明位置”。

### 9.5 建议的分组结果

智能体可以先提出候选分组，让用户确认：

```text
通用照明组：覆盖整个会议室工作面，参与平均照度和均匀度计算
重点照明组：照亮指定墙面、讲台或展示对象，单独评价目标面效果
场景控制组：按会议、演示、视频会议和清洁模式组织
未分类组：证据不足，暂不参与最终结论
```

通用照明和重点照明最好分别建立计算场景。否则重点照明可能提高总平均照度，却没有改善工作面均匀度，导致结果被混在一起，难以解释。

## 10. 候选布灯方案生成

### 10.1 输入约束

生成候选位置前，智能体至少需要确认：

- 房间有效边界；
- 墙体、柱和不可安装区域；
- 家具、会议桌、屏幕和展示面；
- 通用照明和重点照明分组；
- 灯具型号和配光文件；
- 灯具安装高度及旋转方向；
- 目标照度、均匀度、UGR 和功率密度；
- 灯具到墙体、障碍物和彼此之间的最小距离；
- 是否需要分区控制或调光。

缺少上述关键输入时，智能体应先提出待确认事项，而不是生成看似精确的坐标。

### 10.2 通用照明方案

适合矩形房间的第一版方法是：

1. 在有效房间边界内生成候选网格；
2. 排除墙、柱、家具和维护空间；
3. 计算边界退让、行间距和列间距；
4. 根据目标光通量估算灯具数量；
5. 使用配光文件进行快速照度预览；
6. 保留多个满足几何约束的方案；
7. 交由 DIALux 复核真实照度、均匀度和 UGR。

### 10.3 重点照明方案

重点照明应以目标对象为中心生成，而不是把通用网格中的灯随机移动。流程应包括：

1. 确认目标对象的线、面或区域；
2. 计算灯具到目标面的距离和入射方向；
3. 选择合适的灯具配光和旋转角度；
4. 检查灯具是否进入人员视线造成眩光；
5. 对目标面建立垂直照度或亮度评价；
6. 与通用照明分回路或分场景；
7. 在综合场景中复核视觉效果。

### 10.4 方案目标函数

候选方案可以综合以下目标进行排序：

```text
方案评分 =
  照度目标偏差惩罚
  + 均匀度不足惩罚
  + 可能眩光风险惩罚
  + 装机功率惩罚
  + 灯具数量惩罚
  + 间距不规则惩罚
  + 偏离轴网惩罚
  + 与障碍物距离不足惩罚
```

评分权重必须在项目中可见。智能体不能只给出“方案 A 最好”，还应说明方案 A 是因为照度更均匀、功率更低，还是因为施工更简单。

## 11. 当前项目的初步分析示例

根据当前报告中的灯具位置数据，可以观察到：

### 11.1 CDN 灯具

- X 坐标约为 2.000、4.322、6.635 m；
- 纵向坐标大致覆盖 1.8～14.2 m；
- 主要横向间距约为 2.31～2.32 m；
- 纵向间距大多约为 2.46～2.50 m；
- 中间列的覆盖范围与两侧列不完全相同。

它具有明显的规则阵列特征，但中间列并非完整覆盖，因此智能体应检查这是否是有意避让家具或其他建筑对象，还是造成照度空洞的原因。

### 11.2 PAK 灯具

- 坐标主要集中在 X 约 3.209～5.709 m、Y 约 9.866～15.507 m 的区域；
- 多个灯具形成线性或近似线性排列；
- 相邻中心距约为 0.62～0.80 m；
- 报告中还出现约 0.670 m 的阵列中心距。

这说明 PAK 灯具不是均匀覆盖整个房间的简单网格。智能体需要结合其实际旋转方向、灯具外形尺寸、会议桌位置和照明回路，判断它是连续灯带、局部通用照明，还是重点区域照明。

### 11.3 与报告结果的关联

当前报告结果为：

| 指标 | 实际值 | 目标值 | 初步状态 |
|---|---:|---:|---|
| 平均照度 | 656 lx | 750 lx | 不足 |
| 最小照度 | 134 lx | 未单独列出目标 | 需结合均匀度分析 |
| 均匀度 U₀ | 0.20 | 0.60 | 明显不足 |
| 最大 UGR | 20 | 19 | 超出目标 |

因此布局智能体应重点输出：

- 哪些区域的灯具密度较高；
- 哪些区域存在较大的灯具间距或空洞；
- PAK 密集阵列是否产生局部过亮或眩光风险；
- CDN 阵列不完整的中间区域是否对应照度不足；
- 两类灯具的高度、配光和光通量差异是否需要在 DIALux 中分场景验证。

这些是进一步仿真的线索，不能仅凭坐标直接证明因果关系。

## 12. 输出形式

### 12.1 平面图叠加

前端应提供可缩放的平面图叠加层：

- 不同型号使用不同颜色；
- 通用照明、重点照明和未分类使用不同图层；
- 异常灯具显示黄色或红色标记；
- 行列、中心线和测量距离可开关；
- 点击灯具可查看型号、坐标、高度和证据来源；
- 点击问题可定位到对应灯具和原始文件。

### 12.2 灯具位置表

建议字段：

| 字段 | 说明 |
|---|---|
| 编号 | 报告或图纸中的灯具编号 |
| 品牌/型号 | 关联后的最终型号或候选型号 |
| 照明类别 | 通用、重点、未分类或候选分类 |
| X/Y/Z | 米制坐标和安装高度 |
| 旋转角度 | 灯具方向 |
| 最近邻 | 最近灯具编号和中心距 |
| 边界距离 | 到房间边界的最短距离 |
| 所属分组 | 照明组或控制回路候选 |
| 状态 | 正常、警告、错误、待确认 |
| 来源 | DXF 实体、PDF 页码或 DWG 对象 |

### 12.3 问题审查报告

每个问题至少应包含：

- 问题类型；
- 严重程度；
- 涉及的灯具编号；
- 坐标和距离；
- 判断依据；
- 来源文件和页码/实体；
- 推荐动作；
- 是否需要 DIALux 复核。

报告应使用“疑似”“需确认”“不一致”等可审查表述，避免把几何警告写成最终合规结论。

## 13. 在当前代码中的落地建议

### 13.1 后端

- 在 `floor_plan.py` 中增加灯具符号、块、索引和坐标提取；
- 在 `schemas.py` 中增加 `LuminairePlacement`、`LayoutCheck`、`LayoutIssue` 和 `LayoutCandidate`；
- 新增 `calculations/layout.py`，实现距离、边界、阵列、重叠和覆盖分析；
- 在 `tools.py` 暴露 `analyze_luminaire_layout`，供智能体编排；
- 增加 PDF 报告结构化解析器，并保存页码和文本定位；
- 在 `web_api.py` 增加布局分析、候选方案查询和结果导出接口；
- 继续使用项目 revision、文件 SHA-256 和交接包快照，避免布局分析结果与新版本设计混用。

### 13.2 前端

建议增加一个“布局分析”工作区，至少包含：

1. 图纸预览和灯具叠加层；
2. 灯具数量和型号统计；
3. 通用/重点/未分类分组；
4. 问题清单；
5. 间距和边界测量；
6. 方案 A/B/C 对比；
7. 导出位置表和 Markdown 审查报告。

### 13.3 智能体工具边界

模型负责：

- 理解用户意图；
- 组织解析和计算工具；
- 解释异常；
- 询问缺少的设计意图；
- 编排候选方案和 DIALux 交接。

确定性服务负责：

- 坐标变换；
- 距离和面积计算；
- 灯具匹配；
- 阵列识别；
- 重叠和越界判断；
- 方案评分；
- 版本和哈希校验。

LLM 不应自行计算后直接覆盖项目事实，也不应绕过工具输出“照度已经合格”。

## 14. 推荐实施阶段

### 阶段 1：位置提取和一致性审查

先实现：

- DXF 灯具识别；
- PDF 坐标解析；
- DXF/PDF 坐标统一；
- 数量、型号和坐标匹配；
- 位置表和图纸叠加。

验收标准：当前 `512会议室` 能识别 36 套灯具，并能定位每套灯具的来源。

### 阶段 2：几何布局分析

增加：

- 最近邻和行列间距；
- 到墙和障碍物距离；
- 符号外轮廓重叠；
- 阵列缺失和错位；
- 问题标记和审查报告。

验收标准：人为制造漏灯、重复灯、错位灯和过密灯具的测试文件，分析结果能够稳定发现。

### 阶段 3：照明类别和控制分组

增加：

- 通用照明/重点照明候选分类；
- 证据链和置信度；
- 用户确认分组；
- 通用、重点和综合计算场景；
- 场景控制建议。

验收标准：证据不足时必须进入待确认状态，不得自动生成确定性分类。

### 阶段 4：候选布灯和专业复核

增加：

- 约束下候选位置搜索；
- IES/LDT 快速照度预览；
- A/B/C 方案比较；
- DIALux 交接包；
- 仿真结果回灌和快照校验。

验收标准：候选方案能够输出约束、评分和不可行原因；只有与当前交接包匹配的 DIALux 结果才能作为项目结论。

## 15. 最终建议

这个能力值得开发，但建议从“识别与审查”开始，而不是直接做全自动布灯。

最有价值的第一版结果是：

```text
一张带灯具编号、型号、照明类别候选和异常标记的平面图
+ 一张逐灯坐标表
+ 一份 DXF/PDF 一致性报告
+ 一份间距、边界和可能重叠问题清单
+ 一组需要用户确认的通用/重点照明分组
```

在此基础上，再通过配光文件和 DIALux 把几何分析推进到候选方案比较。这样智能体的结论有数据来源、有计算过程、有不确定性标记，也能与现有项目的 RAG、版本控制、灯具资产和 DIALux 交接能力衔接起来。
